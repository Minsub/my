# 취미 · 냉장고

취미 > 냉장고(`/hobby/fridge`)는 냉장고에 무엇이 있는지 한 화면에 보는 페이지다. 아이패드를 냉장고 옆에 세워 두고 쓰는 것을 기준으로 만들었다. 넣고 빼는 수고를 줄이는 게 목표라 **냉장·냉동 두 칸, 이름, 종류, 넣은 날**만 기록한다. 개수·양·유통기한·세부 칸은 적지 않는다. 2026-11-08 코드 기준.

## 화면

- 세 칸: 냉장실 · 냉동실 · 오른쪽(바로 먹을 것 + 이걸로 해먹기). 아이패드 가로(사이드바 포함 1180px)에서 페이지 스크롤 없이 한 화면에 들어가고, 800px 이하에서는 위아래로 쌓는다.
- 종류: **재료**(두부·대파), **반찬**(감자조림·도라지무침·김치찌개 남은 것처럼 만들어 둔 것), **간편식**(냉동 짬뽕·만두·아이스크림처럼 사 온 완성품). 칸 안을 종류별 묶음으로 나눈다. 냉장실은 반찬 → 간편식 → 재료, 냉동실은 간편식 → 반찬 → 재료 순이고 한 종류뿐이면 묶음 제목을 숨긴다. 반찬 타일은 베이지, 간편식은 옅은 보라 바탕이다.
- 타일: 아이콘·이름·넣은 날(오늘, 어제, 그 밖은 M/D). 묶음마다 **오래 둔 것부터** 보여준다.
- 아이콘: 입력받지 않고 종류와 이름에 든 낱말로 고른다(`lib/fridge.ts`의 `fridgeIcon`). 낱말 목록을 위에서부터 보고 처음 맞는 것을 쓴다. 반찬은 찌개·국 🍲, 나물·무침 🥗, 전 🥞 등을 먼저 보고 없으면 🍱, 간편식은 짬뽕·짜장 🍜, 피자 🍕, 만두 🥟 등을 보고 없으면 🍽️, 재료는 없으면 🥡다. 두부는 맞는 이모지가 없어 ⬜를 쓴다.
- 누르기: 타일을 누르면 이름·종류를 고치는 시트가 열린다(칸은 끌어서 옮긴다). 끌기를 마친 손가락이 같은 타일에서 떨어져도 시트는 열지 않는다.
- 빼기: 타일을 **꾹(0.38초) 누른 채로 끌어서** 아래에 올라오는 "다 먹었어요"나 "버렸어요"에 놓는다. 반대 칸에 놓으면 그 칸으로 옮긴다(넣은 날은 그대로). 끄는 동안에는 화면 스크롤과 하단 알림을 막는다.
- 넣기: 머리의 "넣기"나 칸의 ＋. 시트에서 냉장/냉동을 고르고, 쉼표로 이름을 적거나 칩을 누른다. 적은 이름마다 종류를 짐작해(`guessFridgeKind`) "종류 확인" 줄에 보여주고, 틀리면 눌러서 재료 → 반찬 → 간편식으로 바꾼다. 짐작: 짬뽕·짜장·우동·라면·피자·돈까스·너겟·핫도그·아이스크림·볶음밥·만두·밀키트·도시락·김밥·샌드위치가 들어가면 간편식, 조림·무침·볶음·나물·찌개·국·탕·전·장아찌·절임·샐러드·카레·겉절이·잡채·반찬·남은 것으로 끝나면 반찬(설탕·사탕 제외), 나머지는 재료다. 넣은 날은 서버가 서울 날짜 오늘로 정한다.
- 넣기 칩: **자주 넣는 것**은 따로 고르는 즐겨찾기가 아니라, 최근 180일에 넣은 횟수가 많은 순(같으면 최근에 넣은 순) 12개 중 지금 냉장고에 없는 것이다. 칩을 누르면 마지막으로 넣었을 때의 종류로 들어간다. 그 아래 **집밥에 나오는 재료**는 집밥 메인 재료 중 냉장고에 없고 늘 있는 재료도 아니며 자주 넣는 것과 겹치지 않는 것이다.
- 바로 먹을 것: 오른쪽 위에 반찬·간편식을 오래 둔 순으로 모은다. 냉동실 것은 파란 바탕이다.
- 되돌리기: 넣기·빼기·옮기기 직후 알림의 "되돌리기". 넣기는 지우고(`fridge_delete`), 빼기는 되살리고(`fridge_restore`), 옮기기는 원래 칸으로 옮긴다. 확인 창은 없다.
- 이번 달 버린 수를 머리에 보여준다.
- 다른 기기(폰)에서 바꾼 것도 보이도록 화면으로 돌아올 때와 2분마다 다시 읽는다. 끄는 중에는 다시 읽지 않는다.
- 코드: `src/components/fridge-board.tsx`, `src/app/fridge.css`, 진입 카드는 `menu-hub.tsx`의 `hobbyMenus`, 데모 데이터 `src/lib/demo-fridge.ts`. 데모(`/demo?view=/hobby/fridge`)는 화면에서만 바뀌고 저장하지 않는다.

## 이걸로 해먹기

[집밥](../meals/README.md) 요리의 **메인 재료**를 냉장고 재료와 맞춘다(`lib/fridge.ts`의 `matchMeals`).

- 반찬은 이미 만든 음식이라 매칭에서 뺀다("감자조림"이 감자로 잡히지 않게). 간편식은 남긴다(만두 → 만둣국, 냉동밥 → 볶음밥).
- 재료 다 있음은 "지금 바로", 하나만 없으면 "하나만 있으면". 냉장고 재료를 하나도 쓰지 않는 요리는 빼고, 오래 둔 재료를 쓰는 요리가 앞에 온다.
- 이름 맞추기: 같은 이름(띄어쓰기 무시)이 먼저다. 아니면 냉장고 이름이 재료 이름을 품을 때 맞춘다("다진 돼지고기" ↔ 돼지고기, "냉동밥" ↔ 밥). 한 글자 재료("무")는 "단무지"에 걸리지 않도록 같은 이름만 맞춘다.
- 냉동실 재료는 ❄︎로 표시한다(해동 필요). 없는 재료는 점선으로 "없음".
- **늘 있는 재료**(김치·된장·고추장·간장·고춧가루·마늘·참기름·굴소스·두반장·참치)는 냉장고에 적지 않아도 있다고 본다. 화면 설정은 없고 `fridgeStaples` 상수를 고친다.
- 요리를 누르면 그 요리에 쓰는 냉장고 재료를 테두리로 짚고 나머지는 흐리게 한다.

## 저장·권한

- 표: `db/migrations/021_fridge_items.sql`의 `fridge_items`(name 40자, place `cold`/`frozen`, added_on, removed `eaten`/`wasted`, removed_at, version). 022에서 kind(`ingredient`/`dish`/`ready`, 기본 ingredient)를 더했고, 이미 있던 행은 위 짐작과 같은 낱말로 한 번 나눴다. 뺀 것은 지우지 않고 removed를 남겨 버린 수에 쓰고, "자주 넣는 것"은 뺀 것까지 포함한 넣은 기록에서 센다. 넣기 취소만 행을 지운다.
- 조회 `GET /api/fridge`(`{ items, frequent, wasted_this_month }`), 쓰기는 공통 `POST /api/commands`의 `fridge_add`(`items: [{name, kind}]`, 한 번에 20개, 공백·같은 이름 정리)·`fridge_update`(이름·종류)·`fridge_remove`·`fridge_restore`·`fridge_move`·`fridge_delete`(서버 `src/server/fridge.ts`).
- 냉장고는 함께 쓰므로 넣은 사람과 관계없이 공간 안의 누구나 빼고 옮긴다. 같은 재료를 동시에 바꾸면 version 검사(`VERSION_CONFLICT`)로 막고 화면은 서버 목록으로 다시 맞춘다.
- scope: 집밥과 같은 부엌 영역이라 `meal:read`·`meal:write`를 같이 쓴다. 새 scope를 만들면 기존 AI 연결을 다시 승인해야 해서 나누지 않았다.
- MCP: 모든 `fridge_*` 명령이 `webOnlyCommands`라 도구로 나가지 않고 MCP 채널에서 거부한다. 영수증 사진으로 한꺼번에 넣기 같은 MCP 도구는 필요해지면 그때 연다.
