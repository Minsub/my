# 가계부 통합 설계안 A — 기간을 중심으로 읽는 분석 도구

2026-09-09 작성. `cash-money.html`과 `DESIGN.md`의 실제 동작을 분석한 독립 제안이다. 현재 구현 완료 문서가 아니며 최종 구현은 두 제안의 비교 후 결정한다.

## 1. 선택 방향

MONO의 `/cash`를 **대시보드 / 거래 내역 / 파일 관리** 세 탭으로 구성한다. 기존의 연도·분류 피벗 분석은 살리되, 첫 화면은 기간 요약과 추세를 읽기 쉽게 배치한다. PC는 비교표, 모바일은 선택 기간의 분류 순위와 거래 드릴다운을 우선한다.

입력은 계속 기존 가계부 앱에서 한다. MONO에서는 원본 엑셀 업로드와 분석만 제공하고 거래 수정 폼, 거래별 SQL 저장, 파일 버전 보관, 업로드용 MCP는 만들지 않는다.

원본 파일은 Neon `bytea`로 저장한다. 공간과 정규화한 파일명이 같은 파일은 검증 성공 후 최신 내용으로 교체한다. 이름이 다른 파일은 별도 자료다. 파일명에서 확장자를 뺀 값을 표시 이름으로 사용하되 로그인 사용자와 연결된 사람이라고 추정하지 않는다.

## 2. 원본 HTML에서 유지할 가치

| 현재 동작 | MONO에서의 보존 방법 |
|---|---|
| 연도별 수입·지출·월평균·수지·비율 | 연도 요약 표와 기간 KPI로 유지 |
| 수입/지출 분류 × 연도/월 피벗 | 분류 분석의 PC 표 보기로 유지 |
| 대분류에서 소분류로 펼치기 | 분류명 옆 독립 펼치기 버튼 |
| 금액에서 거래 상세 조회 | 모든 합계의 금액 버튼에 같은 필터로 내역 이동 |
| 기타를 내용별로 펼치기 | 분석 옵션으로 유지, 원본 분류는 변형하지 않음 |
| 1,000만 원 이상 지출 제외 | 기본 끔, 켜면 제외 건수·금액을 표시 |
| 수입 분류 포함 / 지출 분류 제외 | 고급 필터에 명시적 의미로 유지 |
| 선물 > 계좌이체 제외 | 기본 분석 제외, 원본 내역에서 확인 가능하게 함 |
| 차트와 증감률 | 시각화와 표에 동일 집계 사용, 직전 달/연도 라벨 명시 |
| 요약 Markdown 내보내기 | 현재 필터·자료 갱신일·집계 규칙까지 포함 |
| 날짜/금액 정렬과 상세 패널 | 검색·결제수단 필터·페이지 단위 표시 추가 |

`DESIGN.md`에는 존재하지만 HTML에 실질 구현이 없는 기능도 있다. 상세 CSV, 항상 표시되는 기본 추세 차트, 모바일 최적화는 기존 기능의 단순 이전이라고 표현하지 않고 신규 구현 범위로 다룬다.

## 3. 실제 코드의 집계 오류와 수정 기준

### 원화와 환불

`normalizeRows()`는 `Number(r["금액"]) || Number(r["KRW"]) || 0` 로직으로 `금액`을 먼저 사용한다. 외화 거래의 `금액`이 원화 금액보다 먼저 선택될 수 있으며 0원도 누락된다. 이후 `Math.abs()`로 음수 부호까지 없앤다.

- 기본 분석 단위는 원이다. 유효한 `KRW`를 우선하고, 없을 때 통화가 KRW인 `금액`만 대체값으로 사용할 수 있다.
- 원래 통화와 원금액은 거래 상세에 보존한다. 원화 금액을 구할 수 없는 외화 거래는 임의 환율로 합산하지 않고 검증 결과에 드러낸다.
- 음수는 원본 부호를 유지한다. 지출 -10,000원은 순지출을 10,000원 낮추는 것으로 처리할 수 있으나, 실제 export의 음수 의미를 표본 확인해 확정한다. 빈 값·0원·오류를 구별한다.
- 모든 합계는 원 단위로 계산하고 화면의 축약 표시는 마지막에만 한다. 상세/내보내기는 정확한 원 단위를 제공한다.

### 완료 월 추정

`computeLastCompleteMonth()`는 마지막 거래일이 월말이면 해당 월, 아니면 전월을 완료로 가정한 뒤 **파일들 중 최댓값**을 고른다. 월말에 거래가 없으면 정상 기록도 미완료로 판단한다. 자료가 덜 갱신된 다른 파일도 합계에 함께 들어가므로 전체 인원이 그 월을 완료했다는 의미도 아니다.

- 거래 날짜만으로 기록 완료 여부를 확정하지 않는다.
- 기본 기간은 기존 습관에 맞춰 `2021-01 ~ 최신 기록 월`로 시작하되 시작 월을 사용자가 바꿀 수 있게 한다. 2021년 이전 데이터도 저장·조회 가능하다.
- 최근 기록 월을 제외하는 옵션은 `최신 기록 월 제외`로 표현한다. 이를 `완료 월만`이라고 부르지 않는다.
- 파일마다 `업로드 일시 / 첫 기록일 / 마지막 기록일`을 표시한다. 전체 자료 중 가장 최근일만 보여주지 않는다.
- 파일별 최근 기록 월이 다르면 “자료의 마지막 기록 월이 서로 다릅니다”와 실제 범위를 보여준다. 이것이 데이터 누락이라는 단정은 피한다.
- 필요하면 후속 기능으로 사용자가 지정하는 `기록 확인 완료 월` 메타데이터를 추가할 수 있지만 첫 업로드를 막는 필수 값으로 두지 않는다.

### 평균과 비교

현재 연도 요약은 완료 월까지의 월 수로 나누고, 분류 피벗은 해당 유형의 마지막 거래가 있는 월 번호로 나눈다. 수입 필터를 바꾸면 평균 분모까지 변할 수 있다. 연도 피벗은 자료가 있는 연도만 만들어 직전 열이 직전 연도가 아닐 수도 있다.

- 평균 분모는 **선택된 달력 기간의 월 수**로 통일한다. 거래 없는 월도 범위 안이면 포함한다. 카드에 `선택 기간 8개월 기준`처럼 명시한다.
- 시간 축은 선택 기간 전체를 생성한다. 거래 없는 월/연도는 합계 0, 범위 밖·아직 비교할 수 없는 월은 비대상으로 구별한다.
- 연도별 평균과 월평균을 섞지 않는다. 컬럼 제목을 `월평균` 또는 `연평균`으로 분명히 적는다.
- 전년 비교는 같은 월까지의 누적으로 맞춘다. 2026년 1~5월과 2025년 전체를 비교하지 않는다.
- 비교 대상이 0이면 `신규 지출` 또는 `비교 기준 없음`, 현재 0이고 이전이 양수이면 -100%를 표시한다. 현재 구현은 현재 금액 0에서 변화율을 생략한다.
- 소득이 0 이하이면 비율은 `—`로 표시한다. `모은 돈`보다 `수지(수입−지출)`를 사용하고, 지출 제외 필터가 켜지면 실제 잔액이나 실제 저축률과 다르다는 계산 설명을 붙인다.

### 날짜와 제외 내역

- 엑셀 일련번호, 날짜 셀, 문자열 날짜를 명시적으로 정규화한다. 브라우저/서버의 타임존과 임의 `new Date(string)` 파싱에 따라 날짜가 이동하면 안 된다.
- 이체·차액 등은 기본 수입·지출 분석에서 제외하되 원본 파일 자체를 보존하고 파일 검증 화면에 유형별 제외 수를 보여준다.
- 중복으로 보이는 거래를 제거하지 않는다. 같은 날 같은 금액의 지출도 별도 행이다. 완전한 파일 교체이므로 거래 식별자 추정이 불필요하다.

## 4. PC 화면

공통 MONO 사이드바 아래 가계부 모듈을 추가한다. 제목은 `가계부.`이며 가족 전용 문구는 쓰지 않는다.

```text
가계부.                                      요약 내보내기  파일 업로드
대시보드       거래 내역       파일 관리

자료 [전체 ▾]   기간 [2021-01] ~ [2026-05]   [필터 2]  초기화
마지막 기록: 민섭 2026-05-… · 장미 2025-12-…

수입             지출             수지             월평균 지출
선택 기간 금액    선택 기간 금액    수입 − 지출       분석 월 수 명시

월별 수입·지출 추세 (넓은 영역)          지출 분류 순위 (상위 6개+더보기)

연도별 요약 표

분류 분석  [지출 / 수입] [연도별 / 월별] [연도] [순위 / 표]
분류 | 기간별 금액·증감 | 합계 | 월평균
```

KPI를 6~8개로 늘려 같은 합계를 반복하지 않는다. 자료 갱신 상태가 필터에 묻히지 않도록 제목 아래에 항상 표시한다. 큰 지출 TOP 5, 결제수단별 지출 순위는 대시보드의 접을 수 있는 하단 영역으로 제공한다.

피벗은 첫 분류 열을 고정하고 표 컨테이너 안에서만 가로로 스크롤한다. 페이지 전체가 가로로 늘어나면 안 된다. 금액 셀은 접근 가능한 버튼이고, 분류 펼치기와 거래 이동을 한 클릭에 겹치지 않는다. 변화는 배경색만으로 설명하지 않고 숫자와 부호를 같이 표시한다.

## 5. 모바일 화면

- 첫 화면은 자료 선택·기간 버튼, 2×2 KPI, 월별 추세, 지출 순위 순서다.
- 기간·포함/제외 옵션은 상단 `필터 N` 버튼으로 여는 전체 폭 패널에 넣는다. 적용/초기화 버튼은 하단에서 항상 접근 가능하다.
- PC 피벗을 강제로 축소하지 않는다. 분류 분석의 기본은 `분류명 / 합계 / 비중 / 이전 기간 대비` 행이며, 누르면 소분류와 월별 흐름, 거래 내역을 본다.
- 월별/연도별 요약은 한 기간씩 접는 행으로 제공한다. `표 보기`는 필요한 사용자가 선택하는 보조 모드다.
- 상세 거래는 날짜별 목록: 내용·분류·자료 표시와 오른쪽 정확한 금액. 결제수단은 두 번째 줄에 표시한다.
- 드릴다운은 전체 높이 패널이나 거래 내역 탭 이동으로 구현한다. 닫기 44px, Escape, 포커스 복귀, 뒤로가기를 지원한다.
- 네비게이션 추가 후 모바일 하단 메뉴가 5개를 넘지 않게 한다. 현재 홈·커피·와인·설정에 가계부를 더해 5개가 되면 가계부를 포함한 5개까지만 유지한다. 장기적으로 홈의 도구 선택을 이용한다.

## 6. 거래 내역과 드릴다운 계약

대시보드의 합계와 상세가 일치해야 한다. 클릭 시 자료·기간·수입/지출·대분류·소분류·분석 제외 조건을 그대로 넘긴다. `내역 137건 · 지출 1,234,567원`처럼 현재 상세 합계를 표시한다.

검색 대상은 내용, 분류, 소분류, 결제수단이다. 날짜 최신순을 기본으로 하고 오래된순·금액 높은순·낮은순을 제공한다. 한 번에 50건을 표시해 1.9만 행을 DOM에 만들지 않는다. 필터와 정렬은 URL에 보존한다. 개인 가계부 내용 자체는 URL에 넣지 않는다.

내역 CSV가 구현 범위에 들어가면 현재 필터만 내보내고 스프레드시트 수식으로 실행될 수 있는 메모를 안전한 텍스트로 이스케이프한다. 요약 Markdown은 상세 거래를 넣지 않는 기존 원칙을 유지한다.

## 7. 파일 관리 경험

자료 카드에는 파일명, 표시 이름, 원본 크기, 유효 거래 수, 기록 범위, 업로드 시각, 업로드한 사용자, 검증 제외 건수를 표시한다.

1. `.xlsx` 다중 선택을 지원한다. 임시 엑셀 파일 `~$`와 0바이트·암호화·읽을 수 없는 파일은 거부한다.
2. 서버가 실제 내용을 파싱·검증한다. 파일 확장자와 클라이언트 미리보기만 신뢰하지 않는다.
3. `새 파일 추가` 또는 `기존 파일 교체`를 명시하고 교체 전후 기간·행수·합계 차이를 보여준다.
4. `적용` 버튼을 누르면 교체한다. 원본은 최신 1개만 남으며 이전 버전 복원 버튼은 제공하지 않는다.
5. 성공 후 모든 가계부 조회를 새 파일 해시 기준으로 갱신한다. 실패한 파일은 이전 파일을 유지한다.

동일 파일명을 키로 사용하므로 한글 NFC 정규화와 앞뒤 공백 제거, 확장자 대소문자 통일을 서버에서 고정한다. 경로 요소·제어 문자·정규화 후 중복된 다중 업로드는 거부한다. 같은 이름으로 두 사람이 동시에 교체할 경우 미리보기에서 확인한 해시와 현재 해시를 비교해 오래된 화면의 덮어쓰기를 막는다.

파일명 변경은 새 자료가 되는 점을 업로드 화면에 짧게 안내한다. 원본 다운로드는 인증·공간 검사 후만 제공한다. 기존 파일을 숨기는 제거 기능이 필요하면 명확한 삭제 확인을 두되, 이름이 비슷하다는 이유로 자동 삭제하지 않는다.

## 8. MONO 구현 경계

- 원본 `bytea`와 메타데이터를 별도 테이블에 저장하고, 거래별 테이블은 만들지 않는다.
- `cash` 데이터는 기존 커피·와인 `snapshot`에 추가하지 않는다. 가계부 전용 서비스에서 Actor와 공간을 검증해 읽고 정규화·집계한다.
- 파일 파싱 결과는 프로세스 내 제한된 캐시를 사용할 수 있다. 키에 공간·파일 ID·내용 해시·파서 버전을 포함하고 메모리 상한을 둔다. 서버리스에서 항상 캐시가 남는다고 가정하지 않는다.
- 같은 정규화·집계 함수를 대시보드, 내역, 내보내기에서 쓴다. 차트가 별도의 계산식을 갖지 않도록 한다.
- 업로드는 4.5MB보다 작은 명시적 상한 또는 분할 업로드가 필요하다. 이번 원본 두 파일 규모에서는 파일별 제한 업로드가 단순하다. 서버에서 실제 압축 해제 크기와 행 수에도 상한을 둔다.
- 웹 전용 요청이다. 기존 MCP coffee/wine scope에 접근 권한이 자동으로 섞이지 않게 하고 이번 작업에서는 가계부 MCP를 노출하지 않는다.

## 9. 구현 우선순위와 검증

첫 구현에서 필요한 것은 파일 교체·원본 다운로드, 기간/자료/포함/제외 필터, KPI·추세·연도 요약·분류 피벗, 거래 검색·드릴다운, 요약 Markdown이다. 추가 가치는 결제수단 순위와 자료별 갱신 범위 표시가 높다. 예산·자동 이상치 경고·자산 잔액·고정비 추정·AI 조언은 이 자료만으로 확정하기 어려워 미룬다.

검증 시나리오:

- 동일 NFC/NFD 한글 파일명을 두 번 올리면 1개의 파일만 있고 최신 내용으로 바뀜.
- 검증 실패·동시 변경 충돌 시 기존 원본과 대시보드가 유지됨.
- 다른 공간의 파일 ID·파일명으로 조회·다운로드·덮어쓰기 불가.
- 환불 음수·0원·외화 원화환산·날짜 직렬/문자열/윤일이 명시된 규칙대로 처리됨.
- 날짜·금액이 같은 2건이 2건으로 유지됨.
- 거래 없는 월이 평균 분모에 포함되고 피벗·KPI·내역·내보내기 합계가 일치함.
- 시작 연도 이전 조회, 자료별 갱신 월 차이, 전체 필터 결과 0건에서도 화면과 안내가 정상임.
- 390px/1440px에서 필터·업로드·탭·드릴다운·뒤로가기·긴 메모·빈 상태·가로 넘침 확인.

선택 이유: 기존 HTML의 강점은 거래를 쉽게 집계하고 금액의 근거까지 내려가는 흐름이다. 이를 유지하면서 파일 관리와 계산 기준을 먼저 명확히 하면, 화면을 새로 만들어도 사용자가 합계를 신뢰할 수 있다.
