# 가계부 통합 설계안 B — 요약에서 원본까지 탐색

2026-09-09 독립 검토안. 원본 `cash-money.html` 1,985줄과 `DESIGN.md`를 검토했다. 이 문서는 구현 완료 목록이 아니며 최종 구현은 통합 설계 문서를 따른다. XLSX 원본을 Neon에 저장하고 공간·파일명별 최신 파일만 유지한다는 사용자 결정을 전제로 한다.

## 1. 핵심 제안

MONO 안의 가계부는 원래 앱에서 작성한 기록을 살펴보는 분석 도구다. 직접 거래 등록·편집은 만들지 않는다. 이름은 메뉴와 제목에서 `가계부`, 기술 경로는 `/cash`처럼 짧게 유지한다. 첫 화면은 최신 거래월의 현황을 보여주고, 긴 기간의 분류 피벗은 별도 분석 탭에 둔다.

**제안 탭: 요약 / 분류 분석 / 거래 내역 / 파일 관리.** 커피와 와인보다 데이터가 많고 필터가 복잡하므로 조회 컴포넌트와 서비스를 별도로 둔다. 전역 Snapshot에 XLSX 원본이나 거래 전체를 넣지 않는다.

## 2. 원본에서 확인한 실제 기능

| 원본 구현 | 이식 제안 |
|---|---|
| 연도별 수입·지출·월평균·모은돈·저축률 | 요약 하단 PC 표, 모바일 연도 카드. `모은돈`은 정확히 `수입−지출`로 표시하고 잔액·자산으로 표현하지 않음 |
| 수입/지출 각각 연도·월 피벗 | 분류 분석에서 수입/지출 전환 + 기간 단위 전환. 필요 시 PC에서 양쪽 비교 가능 |
| 소분류 인라인 펼치기 | PC 행 펼치기 유지, 모바일 분류 상세에서 소분류 순위 |
| 월평균 → 분류 → 소분류 → 거래 상세 | 모든 기기에서 필터가 적용된 거래 탭으로 이동. 현재 필터 보존 + 돌아가기 |
| 분류 평균/합계 셀에서 시계열·막대 모달 | 금액 셀의 숨은 의미를 줄이고 `추이 보기`, `거래 N건` 버튼으로 구분 |
| 지출 전기 대비 ±20% 강조 | 색상 + 부호 + 수치 유지. 전월/전년인지 명시하고 같은 기간·같은 원본 집합 비교 |
| 기타 내용을 분류로 펼치기 | 분석 옵션으로 유지, 기본 꺼짐. 긴 내용은 줄바꿈하고 전체 제목 제공 |
| 수입 포함, 지출 제외, 1,000만원 이상 지출 제외 | 접을 수 있는 분석 조건에 묶고 적용된 조건만 상단 칩에 노출 |
| 선물/계좌이체 지출, 이체·차액 제외 | 분석 기본 규칙으로 유지하되 원본에서 제거하지 않음. 거래 탭에서 제외된 기록을 선택해 검증 가능 |
| 금액 정렬, ESC 상세 닫기 | 날짜·금액 양방향 정렬 + 실제 버튼/키보드 접근, 모바일 별도 거래 화면 |
| MD 집계 다운로드 | 유지. 화면과 같은 필터 및 집계 함수 사용. 파일별 마지막 거래일/업로드일/해시 표시 |
| 상세 CSV 내보내기 | DESIGN에는 있으나 HTML에는 구현 없음. 추가할 경우 필터 결과 기준, 수식 주입 예방 |
| 기본 추이 차트·검색·자산별 분석·TOP 인사이트 | 일부는 문서 제안뿐이고 원본 메인에는 없음. 새 요약에 추이, 분류 순위, 거래 검색, 결제수단 필터 추가 |
| 로그 차트와 최소 막대 크기 | 로그는 부호·0이 있을 때 오해 가능. 초기 구현은 선형축과 분류 선택/표 병행 권장 |
| IndexedDB 폴더 핸들, Chrome/Edge 제한 | 삭제. 표준 웹 파일 선택으로 모바일에서도 업로드 가능 |

## 3. PC 화면

### 공통 상단

왼쪽 `가계부.`와 짧은 설명, 오른쪽 `요약 내보내기`와 `파일 관리`. 그 아래 4개 도메인 탭과 고정된 필터 줄을 둔다. 공통 필터는 원본 이름(전체/파일별), 시작 월·종료 월, 초기화다. 선택 기간을 URL에 보존해 브라우저 뒤로 가기와 탭 간 이동에서 같은 문맥을 유지한다.

### 요약

- 4개 지표: 수입, 지출, 수입−지출, 월평균 지출. 저축률은 수입이 양수일 때만 보조값으로 노출.
- 월별 수입·지출 추이. 데이터가 긴 경우 선택 연도 또는 최근 12개월 구간으로 좁힐 수 있음.
- 지출 분류 상위 목록과 결제수단 순위. 막대·금액·비중을 같이 표시하고 클릭하면 거래 탭으로 이동.
- 연도별 요약 표. 부분 연도는 반드시 `1~5월 · 5개월`처럼 분모를 표시.
- 파일별 최신 날짜가 다르면 차트 바로 위에 `원본별 반영 기간이 다릅니다`와 기간을 펼쳐 볼 수 있게 제공.

### 분류 분석

위에 `지출 / 수입`, `연도별 / 월별`, 월별의 대상 연도 선택. 기본 지출 탭. 수입 포함·지출 제외·고액 제외·기타 펼치기는 `분석 조건` 패널에 놓는다. 표는 첫 분류 열을 고정하고 기간 열만 가로 스크롤한다. 합계·평균 열은 헤더 단위에 분모를 표시한다. 분류명은 소분류 확장, 금액은 거래 보기, 별도 추이 버튼은 차트 보기로 일관되게 통일한다.

### 거래 내역

검색(내용/분류/소분류/결제수단), 수입·지출 유형, 분류, 결제수단, 날짜·금액 정렬. 상단 결과 건수와 수입/지출 합계. 50개씩 페이지를 표시하고 필터 변경 시 1페이지로 복귀. 날짜·원본명·분류/소분류·내용·결제수단·금액을 비교 가능한 표로 보여준다. 각 행 수정 대신 원본 파일명을 확인할 수 있도록 한다.

## 4. 모바일 화면

PC 표를 화면 폭에 축소하지 않는다. 동일한 필터와 집계 결과를 다른 배열로 보여준다.

- 제목 오른쪽 단일 아이콘 버튼 `파일 관리`, 주요 메뉴는 4탭 가로줄. 파일 업로드 버튼은 파일 관리 화면에서 충분한 너비로 제공.
- 원본 선택 + 기간 요약 + `필터 N` 버튼. 나머지 조건은 접이식 패널에 넣어 차트를 아래로 밀지 않음.
- 지표는 2×2, 금액은 축약값 아래 필요 시 정확한 원화값 확인.
- 요약 차트는 휴대폰 높이에 맞게 약 220px. 연도별 요약은 연도/수입/지출/차액/평균을 보여주는 카드.
- 분류 분석의 기본 화면은 선택 기간의 `분류 · 합계 · 평균 · 증감` 순위 목록. 분류를 누르면 해당 분류의 월별 추이와 소분류 목록을 펼침. 전체 피벗은 `표로 보기`로 따로 열 수 있음.
- 거래는 날짜별 목록. 한 행에 내용·금액, 보조 줄에 원본명·분류·결제수단. 긴 내용은 줄바꿈, 금액은 우측 고정.
- PC 우측 패널과 달리 모바일 상세는 전체 높이 화면 또는 충분히 큰 dialog. 닫기, 뒤로 가기, 안전 영역과 키보드 포커스를 보장. 44px 주요 터치 영역.

전역 모바일 메뉴는 홈/커피/와인/가계부/설정 5개로 끝낼 수 있으나 항목 수가 더 늘 때 도구 목록 구조로 바꿔야 한다.

## 5. 파일명 기준 최신 덮어쓰기

### 저장 단위

`cash_files` 1행이 엑셀 원본 1개다. 키는 `(household_id, normalized_filename)`. 원본 바이트(bytea), SHA-256, 크기, 파일 표시명, 업로드한 사용자, 갱신 시각, 동시 업로드 충돌 검사용 revision, 요약 메타데이터를 둔다. revision은 파일 이력 보관이 아니라 현재 행의 갱신 번호다. 이전 파일 바이트는 보관하지 않는다.

파일명은 Unicode NFC로 정규화한다. 현재 macOS 폴더의 이름은 분해형 한글이므로 NFC/NFD를 같은 이름으로 처리해야 한다. 확장자는 `.xlsx`로 통일하고 앞뒤 공백을 정리한다. 경로 구분자, 제어문자, 빈 이름, Excel 임시 잠금파일 `~$...`를 거부한다. 확장자 없는 표시는 데이터 주체의 이름이며 로그인 계정과 자동 연결하지 않는다. 이름을 바꾸면 새 파일로 취급되므로 파일 선택 전에 그 결과를 보여준다.

### 업로드 화면

원본 목록에 파일명, 마지막 업로드, 거래 기간, 총 거래 건수, 파일 크기, 업로드한 사람을 표시한다. `파일 선택`은 다중 XLSX를 지원하며 각 파일마다 `신규` / `덮어쓰기` / `변경 없음` 상태와 이전 대비 기간·건수를 미리 보여준다.

업로드는 선택 → 검증 → 적용으로 이어진다. 사용자에게 핵심 문구는 `같은 이름의 파일은 새 내용으로 대체됩니다. 이전 파일은 앱에 보관하지 않습니다.` 이다. 예상 파일 2개가 선택되면 2개가 모두 검증된 후 한꺼번에 적용하는 방식이 사용자 의도에 가장 잘 맞는다. 요청 크기에 따라 파일별 전송 방식을 쓰더라도 중간 성공 여부를 분명히 표시해야 한다.

일부 기간만 export한 파일도 유효한 파일이므로 일률적으로 거부하지 않는다. 다만 이전보다 시작일이 늦거나 종료일이 빨라지거나 건수가 줄면 `저장된 기간/거래 수가 줄어듭니다`를 적용 전 표시한다. 감소 자체를 오류로 처리하면 사용자 요청인 과거 삭제 반영을 할 수 없다.

동일 해시면 변경 없음으로 처리해 불필요한 파싱·쓰기·새로고침을 줄인다. 다른 기기에서 먼저 덮어썼으면 충돌로 응답하고 현재 파일 정보를 다시 읽도록 한다. 네트워크 실패 시 기존 파일을 그대로 유지한다.

### 파일 접근

웹 인증 Actor와 household 조건을 모든 목록·바이트 조회·업로드·삭제에 적용한다. 업로드는 same-origin 검사와 적절한 크기·빈도 제한을 사용한다. MCP 업로드는 만들지 않고 기존 coffee/wine 토큰으로 접근할 수 없게 웹 전용 서비스로 둔다. 원본 다운로드가 필요하다면 로그인한 접근자에게만 attachment로 제공한다. 파일 바이트는 다른 페이지와 공개 데모에 전달하지 않는다.

## 6. 원본 계산 규칙의 보완

1. **원화 기준:** HTML `normalizeRows` 438행은 `금액 || KRW`로 계산한다. 외화 금액이 존재하면 원화 합계가 틀린다. `KRW`를 우선 사용하고 원본 통화·금액은 별도 메모리 속성으로 유지한다. KRW가 없고 원화임을 확인할 수 있을 때만 금액으로 대체한다. 0과 공란을 구분한다.
2. **음수:** `Math.abs`는 환불을 지출로 더하는 결과를 낳을 수 있다. 원본 부호를 보존하고 환불/취소는 같은 유형의 합계에서 차감하도록 명시한다. 실제 파일 부호 분포는 구현자가 개인정보 출력 없이 확인한다.
3. **날짜:** JavaScript Date의 시간대에 의존하는 문자열 파싱을 없애고 Excel serial/문자열/날짜 셀을 모두 날짜 문자열 `YYYY-MM-DD`로 정규화한다. 잘못된 날짜와 형식은 경고 건수 또는 검증 오류로 알려준다.
4. **완료 월:** 원본 458행은 파일별 마지막 거래가 월말이면 해당 월, 아니면 전월로 정하고 최댓값을 전체 종료로 쓴다. 월말 무거래일과 입력 미완료는 구분할 수 없으므로 `완료`라고 단정하지 않는다. 기본적으로 최신 거래월까지 보여주고 `마지막 거래일`로 표시하는 안을 권장한다. 필요 시 사용자가 파일별 기록 완료 월을 지정하는 선택 설정을 추가한다.
5. **서로 다른 기간:** 한 파일의 끝이 이르면 합계에서 해당 파일이 없는 최신 월을 0지출인 것처럼 묵시적으로 취급하지 않는다. 파일별 범위를 표시하고 비교 시 동일 파일 집합/기간을 사용한다. 데이터 존재만으로 수입이 없다고 단정할 수 없음.
6. **평균 분모:** 원본 947행은 필터 후 마지막 거래월을 분모로 쓴다. 분류를 제외할 때 평균 기간까지 변하는 오류다. 월평균은 선택된 달력 개월 수를 기준으로 고정하며 거래가 없는 달도 포함한다. 분석 기간 밖이나 미확인 기간은 빈값과 구분한다.
7. **2021년:** 원본은 모든 조회를 2021년 이후로 클램프한다. 저장된 원본은 전부 유지하고 기본 시작만 2021년으로 둔다. 전체 기간 선택으로 더 오래된 기록도 확인할 수 있게 하는 것이 자연스럽다.
8. **증감률:** 전기 0은 비교 불가, 현재 0/전기 양수는 -100%, 선택 시작 이전 기간과 비교할 때도 동일 필터 적용. 부분 연도와 온전한 연도 전체 비교를 피하고 동일 월 범위로 비교한다.
9. **표시:** 0원은 `0원`, 데이터 없음은 `—`. `수입−지출`을 실제 자산 증가나 계좌 잔액으로 표현하지 않는다. 로그 축이 필요하면 음수·0을 숨기지 않는 설명이 선행되어야 한다.
10. **내보내기:** HTML export는 선택 기간과 실제 전체 computedEnd가 어긋날 수 있다. 다운로드에는 실제 조회 범위, 분모, 제외 필터, 참여 파일, 파일 반영 시각을 기록한다. MD에 들어가는 분류/메모 특수문자도 이스케이프한다.

## 7. 구현 경계 및 실패 처리

`src/server/cash-files.ts`는 인증된 파일 저장/조회, `src/lib/cash-parser.ts`는 원본 파싱, `src/lib/cash-analysis.ts`는 순수 집계, `src/components/cash-dashboard.tsx` 및 파일 관리 컴포넌트는 표시를 맡긴다. 거래의 행별 영속화는 하지 않으며 캐시가 필요하면 `(household_id, file_hash, parser_version)`로 격리한다. 프로세스 메모리 캐시는 재시작되어도 원본에서 복구될 수 있는 보조 수단이다.

- 파일 확장자만 믿지 않고 XLSX ZIP/워크북 구조·필수 컬럼·시트·행 수·압축 해제 크기를 검증한다. 매크로나 외부 링크·수식을 실행하지 않는다.
- 인증 실패는 로그인 안내, 권한 실패는 접근 불가, 형식 실패는 파일별 이유, 연결 실패는 기존 대시보드를 유지한 재시도 상태로 구분한다.
- 모바일에 대량 원본을 매번 보내기보다 서버에서 파싱·필터·집계하여 필요한 결과만 전송한다. 서버리스 캐시 미스에서도 두 초기 파일을 처리할 수 있는지 측정한다.
- 로딩은 대시보드 영역 스켈레톤으로 하고 커피·와인의 로딩과 분리한다.
- 빈 파일 또는 유효 수입/지출 0건은 곧바로 기존 파일을 지우지 않도록 적용 전 빈 결과를 명확하게 표시한다. 누락 컬럼과 손상파일은 실패 처리한다.

## 8. 검증 기준

- 한글 NFC/NFD 파일명이 같은 저장 키가 되고 다른 공간의 같은 이름은 서로 영향을 주지 않는다.
- 같은 이름 업로드는 1행 유지, 신규 이름은 1행 증가, 동일 내용 재시도는 멱등, 실패·충돌 시 이전 바이트 유지.
- 원화/외화, 음수 환불, 0, Excel 날짜, 누락 컬럼, 손상파일, 초과 크기 검증.
- 필터·분류·기타 펼치기·원본 선택·기간과 다운로드가 같은 수치를 사용.
- 월평균은 마지막 거래 발생 여부나 분류 필터로 분모가 변하지 않음.
- 390px/1440px에서 업로드·파일 교체·조회·검색·정렬·분류에서 거래 이동·뒤로 가기·긴 제목·빈 데이터 확인.
- 초기 두 XLSX는 운영 권한 있는 사람이 동일 저장 서비스로 최초 적재. 원본 파일·상세 거래 데이터는 테스트 fixture나 커밋에 포함하지 않음.
