# 와인 셀러 목록과 사진

Vivino Wine Explorer의 가격·국가·지역·품종 필터를 실제 구매 기록에 맞게 적용했다. 참고: https://www.vivino.com/en/explore

## 가격과 통계

- 병당 최근 구입가와 구입일을 목록·상세·MCP `wine_list`/`wine_get`에서 확인한다. 취소된 입고는 제외한다. 같은 날에는 입고 기록 생성 시각을 비교한다.
- 입고 1건(`wine_purchases`)마다 병당 가격을 따로 보존한다. 표시 가격은 평균이 아니라 최근 유효 입고가이고, 추정 가치도 현재 재고 × 최근 구입가다. 소비는 입고 건과 연결하지 않는 재고 합계 차감이라 선입선출 원가를 계산하지 않는다.
- 입고 후 가격은 상세의 `가격 수정`(표시 중인 가격)이나 구매 내역의 연필 버튼(입고 건별)으로 고친다. 웹·MCP 모두 `wine_update_price`를 사용하며 병당 가격만 바꾸고 수량·구매일·재고 이벤트는 그대로 둔다. 입고 건의 수량이 틀렸으면 입고를 취소하고 다시 입고한다. 입고한 사람 또는 관리자만 고칠 수 있고, 취소된 입고는 고칠 수 없으며, 와인 version으로 동시 수정을 막는다(수정 시 version이 올라 사진 주소도 한 번 바뀐다). 구매 내역 없는 이관 와인은 같은 명령에서 purchase_id 없이 참고 가격을 고친다(와인 등록자 또는 관리자).
- 수량 수정: 상세의 `수량 수정`에서 실제 보유 병 수(0~1,000)와 사유(선택, 200자)를 넣으면 기록상 재고와의 차이만큼 `adjust` 이벤트(기록 목록의 "수량 조정")를 남긴다. 구매 내역·가격은 바꾸지 않으므로 늘린 병의 가치는 최근 구입가로 계산된다. 새로 산 병은 입고, 마신 병은 소비로 기록하고 이 기능은 세다가 틀린 수량을 맞출 때만 쓴다. 공간 구성원 누구나(`wine:write`) 할 수 있고, 화면에서 본 재고와 저장 시점 재고가 다르면 거부한다. 같은 수량·보관한 와인은 거부한다. 조정도 기록 옆 되돌리기 버튼(`wine_reverse_event`)으로 취소할 수 있다(재고가 음수가 되면 거부). MCP `wine_adjust_stock`도 같은 규칙이다.
- 와인 삭제: 잘못 등록한 와인은 상세의 `삭제`에서 와인 이름을 그대로 입력해 지운다. 구매 내역·재고 기록(취소 포함)·모든 구성원의 시음 기록·사진이 함께 지워지며 되돌릴 수 없다. 와인 등록자 또는 관리자만, 현재 version일 때만 가능하다. 웹 전용 명령 `wine_delete`이며 MCP 도구로 내보내지 않는다. 공유 링크에 들어 있던 와인은 공개 페이지에서 빠지고 "공유한 목록"의 득표 순위에는 "삭제된 와인"으로 남는다. 더 이상 갖고 있지 않은 와인은 삭제가 아니라 `보관하기`를 쓴다.
- Airtable 이관 가격·날짜는 별도 참조 필드로 보존한다. 원본보다 새로운 유효 구매 내역이 있으면 해당 가격을 사용한다. 새로운 구매가의 공란을 과거 가격으로 덮지 않는다.
- 가격·구입일·등록일·이름·빈티지·재고·사용자 평점으로 정렬한다. 모르는 값은 항상 마지막에 표시한다.
- 국가·지역·품종·빈티지·가격 범위·구입 기간·사용자 평점(100점 척도)·재고·보관함 필터를 지원한다. URL에 조건을 보존한다.
- 필터는 **다중 선택**이다. 종류·국가·가격 구간·지역·빈티지·품종은 칩을 여러 개 고를 수 있고, 같은 항목 안에서는 하나라도 맞으면(OR), 항목끼리는 모두 맞아야(AND) 결과에 남는다. URL에는 쉼표로 담는다(`type=레드,화이트&band=3-5,5-10`). 같은 칩을 다시 누르면 그 값만 빠지고 "전체"·"해제"는 그 항목을 비운다. 대시보드의 종류·국가 버튼도 같은 방식으로 더하고 뺀다.
- 검색창 아래 빠른 필터 칩: 종류(샴페인·기타 스파클링 분리)·국가·가격 구간(3만 미만 / 3–5만 / 5–10만 / 10만 이상). 칩 옆 숫자는 다른 항목은 그대로 두고 그 항목에서 그 값만 골랐을 때 남는 와인 종 수이며, 0인 칩은 숨긴다(선택 중이면 표시). 국가 칩은 고른 국가를 앞에 둔다. 가격 구간은 `band` 키(u3·3-5·5-10·10u)로 저장하고 경계는 29,999·49,999·99,999원이다. 예전 주소의 최소·최대 구입가가 구간과 정확히 같으면 열 때 band로 옮긴다. 상세 필터에는 구입 시기 프리셋(최근 3개월·올해·작년, 하나만 선택), 지역·빈티지·품종 칩, 가격 직접 입력·구입일·평점을 둔다. 국가를 바꾸면 남은 국가에 없는 지역 선택은 버린다. 적용된 필터 표시는 고른 값마다 칩 하나이며 누르면 그 값만 뺀다.
- 결과 줄에 걸러진 와인의 종·병 수와 합계(재고 × 최근 구입가), 병당 평균, 가격 미입력 병 수를 표시한다. 재고 0인 와인은 합계에 들어가지 않는다.
- 760px 이하에서는 대시보드를 "보유·추정 가치(만원)·이번 달 소비" 한 줄 요약으로 접고 눌러서 펼친다. PC는 항상 펼친다. 펼침 상태는 저장하지 않는다.
- 국가·지역·빈티지·품종은 보유 중인 값만 칩으로 고른다. 품종 목록은 `grapes`를 쉼표·슬래시·가운뎃점으로 나눈 개별 품종이며, 블렌드 와인은 구성 품종 중 하나만 선택해도 결과에 포함한다. URL에 목록 밖의 값이 있으면 그 값을 칩으로 더해 해제할 수 있게 한다. MCP `wine_list`도 같은 규칙이라 type·country·region·grape·vintage에 쉼표로 여러 값을 넣을 수 있다.
- 대시보드는 보관하지 않은 현재 재고 기준이다. 종류·국가별 병수, 와인 종류 수, 최근 구입가×재고의 추정 가치와 가격 확인 비율, 한국 시간 기준 이번 달 소비량을 표시한다. 국가/종류 버튼으로 목록을 좁힌다.
- 샴페인은 프랑스 + Champagne/샹파뉴/샴페인 지역의 스파클링을 분리하며, 기타 스파클링과 중복 집계하지 않는다. Vivino 시장 가격이나 평점으로 오해하지 않도록 실제 구입가·사용자 평점으로 표시한다.

## 사진 등록

와인 상세의 사진 업로드에서 JPEG/PNG/WebP를 선택한다. 휴대폰 사진 선택기에서 촬영한 사진도 이용할 수 있다. 웹 입력은 20MB까지 받아 브라우저에서 축소한다. HEIC는 지원하지 않으므로 JPEG로 변환한다.

MCP 사용 예:
1. `wine_create`로 와인을 등록한다.
2. 클라이언트가 실제 파일을 읽을 수 있으면 `wine_upload_photo`에 `wine_id`, `expected_version`, `idempotency_key`(UUID), `image_base64`를 전달한다. 원본 파일은 최대 2MB이고 data URL 접두사는 제외한다.
3. 클라이언트가 첨부파일 바이트를 도구에 전달할 수 없으면 `wine_photo_upload_link`로 로그인 업로드 화면을 연다. Claude·ChatGPT·Codex 모두가 첨부 이미지를 자동으로 base64 도구 인자에 변환한다고 가정하지 않는다.
4. 사진을 교체하려면 최신 `wine_get`의 version을 사용한다. 통신 재시도는 같은 키와 같은 입력을 사용한다.

웹 사진 검색 출처는 Vivino 검색 링크로 통일했다. 이름·생산자·빈티지를 확인한 사진을 선택해서 올린다. 웹 검색 결과를 자동으로 매칭하거나 크롤링하는 기능은 포함하지 않는다.

## 저장과 접근

- 사진은 1,000px 이내 WebP, 최대 300KB로 정규화하고 EXIF/위치정보를 제거한다. 원본은 저장하지 않는다.
- 현재 소규모 개인 앱에서는 Neon의 별도 `wine_photos` 테이블에 대표 사진 한 장을 저장한다. 64장의 최대 사진 데이터는 약 19.2MB이고, 실제 라벨 사진은 장당 약 29KB(750×1000)라 64장이면 약 1.8MB다. 사진이 많아지면 이 테이블의 content를 비공개 오브젝트 저장소로 옮기고 인증 라우트는 유지할 수 있다.
- 셀러 사진 주소는 공개되지 않는다. `/api/wine/{id}/photo`는 가족 로그인 또는 `wine:read` OAuth 토큰을 검증한다. 로그인 없이 보이는 사진은 유효한 공유 링크에 든 와인뿐이다(아래 목록 공유). 캐시는 브라우저 전용(private)이다. 화면은 `?v=version`으로 요청해 1년 immutable로 캐시하고, 사진을 바꾸면 version이 올라 주소가 바뀐다. `?v=` 없는 요청은 no-store다. 일반 목록 응답에는 사진 바이트를 싣지 않는다.
- 사진은 모두 세로(약 3:4)로 올라온다는 전제로 화면을 짠다. 목록 기본 보기는 3:4 사진 카드 격자다(PC는 칸 폭 210px 이상으로 자동 배치, 760px 이하는 2열). 사진은 자르지 않고(contain) 칸을 채운다. 카드 위에 보유 병수, 재고 0이면 흐리게 "재고 없음"을 표시한다. 목록에는 입고·소비 버튼을 두지 않는다(상세에서 처리). 사진·이름을 누르면 상세로 가고, 사진 오른쪽 위 확대 버튼은 상세로 가지 않고 사진을 크게 연다(Esc·바깥 클릭·닫기 버튼으로 닫음). 썸네일과 같은 주소라 추가 전송이 없다.
- 결과 줄의 보기 전환으로 촘촘한 목록(`view=list`)을 고를 수 있다. 한 화면에 많은 와인을 보는 용도라 한 줄에 3:4 썸네일(PC 60px, 모바일 54px 폭)·이름(최대 2줄)·영어 이름·"종류 · 빈티지 · 나라 · 지역"과 오른쪽 가격·보유 병수(평점)만 둔다. 구입일·가격 출처·품종·관리 번호는 상세에서 본다. 줄 전체가 상세 링크다. 1100px 이상은 2열. 재고 0은 사진을 흐리게 한다. 보기 방식은 URL에 남고 필터 초기화에서도 유지한다.
- 상세는 PC에서 왼쪽 열(최대 400px)에 3:4 사진과 사진 업로드를 두고 스크롤해도 고정한다. 사진 높이는 화면 높이를 넘지 않는다. 오른쪽에 정보·버튼·기록·시음 노트가 이어진다. 800px 이하에서는 사진(화면 높이 72% 이내) → 정보 → 기록 → 사진 업로드 순서다. 사진을 누르면 크게 연다.
- 목록 썸네일은 `loading="lazy"`라 화면에 가까워진 행의 사진만 요청한다. 상세의 큰 사진은 바로 받는다. 목록 데이터는 snapshot으로 전체를 받아 브라우저에서 필터·집계하므로 서버 페이징은 두지 않는다. 와인이 수백 종을 넘으면 다시 검토한다.
- 사진 수정은 등록자/관리자, `wine:write`, 현재 버전 검사를 적용한다. 비활성 가족 구성원은 거부한다. 중복 키는 원자적 DB 트랜잭션으로 처리한다.
- `db:export`는 photos 배열에 압축 사진의 base64를 포함한다. 이는 도메인 백업이며 전체 복구에는 pg_dump를 사용한다.

## 목록 공유

와인 모임 사람들에게 후보를 보여주고 어떤 와인을 선호하는지 받으려는 기능이다. 받는 사람은 로그인하지 않는다.

- 만들기: 셀러에서 필터로 추린 뒤 결과 줄의 "공유"를 누른다. 시트에서 제목·안내·가격 표시(가격대 / 정확한 가격 / 숨김, 기본 가격대)·한 사람이 고를 수 있는 수(1~10, 기본 3)·결과 공개 여부를 정하고, 목록에서 뺄 와인의 체크를 푼다. 지금 화면 순서대로 1번부터 번호가 붙는다. 한 링크에 60종까지.
- 저장: 웹 전용 명령 `wine_share_create`(scope `wine:write`). 필터 조건이 아니라 **와인 id 목록을 고정**하므로 재고가 바뀌어도 목록과 번호는 그대로다. 같은 공간의 와인인지 서버가 확인한다. 토큰은 32자 무작위(192bit)이고 유효기간은 14일 고정이다. MCP 도구로는 내보내지 않는다.
- 공개 페이지 `/share/wine/{token}`: 와인 정보는 볼 때의 값(이름·사진을 고치면 반영)이다. 가격은 셀러와 같은 최근 구입가 기준으로 계산해 가격대(셀러의 가격 칩과 같은 구간) 또는 원 단위로 표시한다. 재고·구입일·평점·시음 노트·작성자는 내보내지 않는다. 사진은 `/api/share/wine/{token}/photo/{wine_id}`가 공유에 든 와인만 돌려주며 캐시는 private 1시간이다. 페이지와 사진에 `noindex`·`Referrer-Policy: no-referrer`를 붙인다. 카카오톡 미리보기를 위해 og 제목·설명·첫 사진을 넣고 `htmlLimitedBots`에 `kakaotalk-scrap`을 더했다.
- 외부 정보 링크: 카드마다 "지식백과"(네이버 지식백과 검색, 한글 이름)와 "Vivino"(영어 이름이 있을 때만) 링크를 새 탭으로 연다. 와인을 잘 모르는 사람이 맛·품종·음식 궁합을 읽으라는 용도다. 검색어는 이름에서 괄호 설명과 연도를 뺀다(빈티지가 들어가면 다른 와인이 섞인다). Vivino는 영어 이름에 생산자 단어가 하나도 없으면 생산자를 앞에 붙인다. 지식백과는 와인21·「1001 와인」 등에 있는 와인만 찾고 정확한 와인이 2~3번째일 수 있다. 비교한 다른 후보(데일리샷·와인21 직접 검색·와인나라 등)는 검색이 엄격하거나 판매 상품만 나와서 쓰지 않았다. 규칙은 `lib/wine-cellar.ts`의 `wineInfoLinks`.
- 고르기: 카드의 "고르기"로 최대 N개를 고르고 이름(30자)·한마디(300자)를 보낸다. 브라우저 localStorage의 voter_key로 한 사람을 구분해 다시 보내면 덮어쓴다(다른 기기·시크릿 창은 새 사람). `POST /api/share/wine/{token}/vote`는 같은 출처·IP당 분당 20회·4KB·공유당 100명을 제한하고, 고른 와인이 공유 목록 안에 있는지 확인한다. 결과 공개를 켜면 받은 사람도 와인별 선택 수를 본다.
- 결과·끄기: `/wine/shares`(나의 셀러 옆 "공유한 목록" 탭)에서 와인별 득표 순위·고른 사람·한마디를 본다. "링크 끄기"(`wine_share_revoke`, 만든 사람 또는 관리자)는 즉시 페이지·사진·투표를 막는다. 끈 공유와 받은 선택은 지우지 않는다. 다시 열기와 기간 연장은 없다. 새로 만든다.
- 만료·끈 링크와 없는 토큰은 "공유가 끝났어요"/"링크를 찾을 수 없어요" 화면을 200으로 보여준다.
