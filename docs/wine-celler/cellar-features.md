# 와인 셀러 목록과 사진

Vivino Wine Explorer의 가격·국가·지역·품종 필터를 실제 구매 기록에 맞게 적용했다. 참고: https://www.vivino.com/en/explore

## 가격과 통계

- 병당 최근 구입가와 구입일을 목록·상세·MCP `wine_list`/`wine_get`에서 확인한다. 취소된 입고는 제외한다. 같은 날에는 입고 기록 생성 시각을 비교한다.
- 입고 1건(`wine_purchases`)마다 병당 가격을 따로 보존한다. 표시 가격은 평균이 아니라 최근 유효 입고가이고, 추정 가치도 현재 재고 × 최근 구입가다. 소비는 입고 건과 연결하지 않는 재고 합계 차감이라 선입선출 원가를 계산하지 않는다.
- 입고 후 가격은 상세의 `가격 수정`(표시 중인 가격)이나 구매 내역의 연필 버튼(입고 건별)으로 고친다. 웹·MCP 모두 `wine_update_price`를 사용하며 병당 가격만 바꾸고 수량·구매일·재고 이벤트는 그대로 둔다. 수량이 틀렸으면 입고를 취소하고 다시 입고한다. 입고한 사람 또는 관리자만 고칠 수 있고, 취소된 입고는 고칠 수 없으며, 와인 version으로 동시 수정을 막는다(수정 시 version이 올라 사진 주소도 한 번 바뀐다). 구매 내역 없는 이관 와인은 같은 명령에서 purchase_id 없이 참고 가격을 고친다(와인 등록자 또는 관리자).
- Airtable 이관 가격·날짜는 별도 참조 필드로 보존한다. 원본보다 새로운 유효 구매 내역이 있으면 해당 가격을 사용한다. 새로운 구매가의 공란을 과거 가격으로 덮지 않는다.
- 가격·구입일·등록일·이름·빈티지·재고·사용자 평점으로 정렬한다. 모르는 값은 항상 마지막에 표시한다.
- 국가·지역·품종·빈티지·가격 범위·구입 기간·사용자 평점(100점 척도)·재고·보관함 필터를 지원한다. URL에 조건을 보존한다.
- 검색창 아래 빠른 필터 칩: 종류(샴페인·기타 스파클링 분리)·국가·가격 구간(3만 미만 / 3–5만 / 5–10만 / 10만 이상). 칩 옆 숫자는 다른 조건은 그대로 두고 그 칩만 골랐을 때 남는 와인 종 수이며, 0인 칩은 숨긴다(선택 중이면 표시). 같은 칩을 다시 누르면 해제한다. 가격 구간은 기존 최소·최대 구입가(모두 포함) 값으로 저장하므로 경계가 겹치지 않게 29,999·49,999·99,999원으로 끊는다. 상세 필터에는 지역·빈티지·품종·가격 직접 입력·구입일·평점과 구입 시기 프리셋(최근 3개월·올해·작년)을 둔다. 적용된 필터 표시에서 구간·프리셋과 정확히 같은 값이면 "가격: 3–5만"처럼 한 칩으로 합친다.
- 결과 줄에 걸러진 와인의 종·병 수와 합계(재고 × 최근 구입가), 병당 평균, 가격 미입력 병 수를 표시한다. 재고 0인 와인은 합계에 들어가지 않는다.
- 760px 이하에서는 대시보드를 "보유·추정 가치(만원)·이번 달 소비" 한 줄 요약으로 접고 눌러서 펼친다. PC는 항상 펼친다. 펼침 상태는 저장하지 않는다.
- 국가·지역·빈티지·품종은 보유 중인 값만 드롭다운으로 고른다. 품종 목록은 `grapes`를 쉼표·슬래시·가운뎃점으로 나눈 개별 품종이며, 블렌드 와인은 구성 품종 중 하나만 선택해도 결과에 포함한다. URL에 목록 밖의 값이 있으면 그 값을 선택지에 더해 표시한다.
- 대시보드는 보관하지 않은 현재 재고 기준이다. 종류·국가별 병수, 와인 종류 수, 최근 구입가×재고의 추정 가치와 가격 확인 비율, 한국 시간 기준 이번 달 소비량을 표시한다. 국가/종류 버튼으로 목록을 좁힌다.
- 샴페인은 프랑스 + Champagne/샹파뉴/샴페인 지역의 스파클링을 분리하며, 기타 스파클링과 중복 집계하지 않는다. Vivino 시장 가격이나 평점으로 오해하지 않도록 실제 구입가·사용자 평점으로 표시한다.

## 사진 등록

와인 상세의 사진 업로드에서 JPEG/PNG/WebP를 선택한다. 휴대폰 사진 선택기에서 촬영한 사진도 이용할 수 있다. 웹 입력은 20MB까지 받아 브라우저에서 축소한다. HEIC는 지원하지 않으므로 JPEG로 변환한다.

MCP 사용 예:
1. `wine_create`로 와인을 등록한다.
2. 클라이언트가 실제 파일을 읽을 수 있으면 `wine_upload_photo`에 `wine_id`, `expected_version`, `idempotency_key`(UUID), `image_base64`를 전달한다. 원본 파일은 최대 2MB이고 data URL 접두사는 제외한다.
3. 클라이언트가 첨부파일 바이트를 도구에 전달할 수 없으면 `wine_photo_upload_link`로 로그인 업로드 화면을 연다. Claude·ChatGPT·Codex 모두가 첨부 이미지를 자동으로 base64 도구 인자에 변환한다고 가정하지 않는다.
4. 사진을 교체하려면 최신 `wine_get`의 version을 사용한다. 통신 재시도는 같은 키와 같은 입력을 사용한다.

웹 사진 검색 출처는 Vivino 검색 링크로 통일했다. 이름·생산자·빈티지를 확인한 사진을 선택해서 올린다. 웹 검색 결과를 자동으로 매칭하거나 크롤링하는 기능은 포함하지 않는다.

## 저장과 접근

- 사진은 1,000px 이내 WebP, 최대 300KB로 정규화하고 EXIF/위치정보를 제거한다. 원본은 저장하지 않는다.
- 현재 소규모 개인 앱에서는 Neon의 별도 `wine_photos` 테이블에 대표 사진 한 장을 저장한다. 64장의 최대 사진 데이터는 약 19.2MB이고, 실제 라벨 사진은 장당 약 29KB(750×1000)라 64장이면 약 1.8MB다. 사진이 많아지면 이 테이블의 content를 비공개 오브젝트 저장소로 옮기고 인증 라우트는 유지할 수 있다.
- 공개 URL이 없으며 `/api/wine/{id}/photo`는 가족 로그인 또는 `wine:read` OAuth 토큰을 검증한다. 캐시는 브라우저 전용(private)이다. 화면은 `?v=version`으로 요청해 1년 immutable로 캐시하고, 사진을 바꾸면 version이 올라 주소가 바뀐다. `?v=` 없는 요청은 no-store다. 일반 목록 응답에는 사진 바이트를 싣지 않는다.
- 사진은 모두 세로(약 3:4)로 올라온다는 전제로 화면을 짠다. 목록 기본 보기는 3:4 사진 카드 격자다(PC는 칸 폭 210px 이상으로 자동 배치, 760px 이하는 2열). 사진은 자르지 않고(contain) 칸을 채운다. 카드 위에 보유 병수, 재고 0이면 흐리게 "재고 없음"을 표시한다. 사진·이름을 누르면 상세로 가고, 사진 오른쪽 위 확대 버튼은 상세로 가지 않고 사진을 크게 연다(Esc·바깥 클릭·닫기 버튼으로 닫음). 썸네일과 같은 주소라 추가 전송이 없다.
- 결과 줄의 보기 전환으로 예전 행 목록(`view=list`)을 고를 수 있다. 행 목록에서는 사진을 누르면 크게 열고, 사진이 없으면 그림과 이름 모두 상세로 이동한다. 보기 방식은 URL에 남고 필터 초기화에서도 유지한다.
- 상세는 PC에서 왼쪽 열(최대 400px)에 3:4 사진과 사진 업로드를 두고 스크롤해도 고정한다. 사진 높이는 화면 높이를 넘지 않는다. 오른쪽에 정보·버튼·기록·시음 노트가 이어진다. 800px 이하에서는 사진(화면 높이 72% 이내) → 정보 → 기록 → 사진 업로드 순서다. 사진을 누르면 크게 연다.
- 목록 썸네일은 `loading="lazy"`라 화면에 가까워진 행의 사진만 요청한다. 상세의 큰 사진은 바로 받는다. 목록 데이터는 snapshot으로 전체를 받아 브라우저에서 필터·집계하므로 서버 페이징은 두지 않는다. 와인이 수백 종을 넘으면 다시 검토한다.
- 사진 수정은 등록자/관리자, `wine:write`, 현재 버전 검사를 적용한다. 비활성 가족 구성원은 거부한다. 중복 키는 원자적 DB 트랜잭션으로 처리한다.
- `db:export`는 photos 배열에 압축 사진의 base64를 포함한다. 이는 도메인 백업이며 전체 복구에는 pg_dump를 사용한다.
