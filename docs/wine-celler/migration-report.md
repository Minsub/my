## 보존 방식

- 와인 이름·영문명·종류·국가·지역·품종·빈티지는 `wines`에 저장합니다. 빈티지 공란은 미상으로 유지합니다.
- 현재 재고는 이관일의 `opening_balance`로 저장합니다. 원본에 없는 구매 수량·소비 이력은 추정하지 않습니다.
- 구매가 60건·구매일 64건과 기존 표시 ID를 포함한 **수집한 원본 업무 필드 전체**는 `import_records.raw`에 저장합니다. 구매 수량을 알 수 없어 `wine_purchases`에는 가상의 구매 이력을 만들지 않습니다. 004 마이그레이션은 원본을 보존하면서 `wines.reference_price/reference_purchased_on`에도 복사해 목록·상세·MCP와 정렬에 사용합니다.
- 원본의 시음 노트와 점수는 모두 비어 있습니다. 재구매 체크 2건은 날짜 미상의 이관 취향 기록으로 저장합니다. 기본값인 미체크만으로 시음 이력을 만들지 않으며, 미체크 값도 원본 JSON에 보존합니다.
- 원래 Airtable의 레코드 ID로 중복을 방지합니다. 앱의 표시 번호는 새로 부여되며 기존 번호는 원본 필드에서 확인할 수 있습니다.
- `시음 노트`/`시음노트`, `재구매 의사`/`재구매의사` 두 표기를 모두 지원하도록 이관 파서를 보완했습니다.

## 백업과 검증

비공개 원본과 운영 반영 전 도메인 백업은 Git에서 제외된 `backups/airtable-2026-09-08/`에 저장했습니다. 원본 JSON·상세 화면 수집 기록·운영 반영 전 데이터가 포함되며, 전체 시스템 복구용 인증 DB 백업은 아닙니다.

개발 DB에서 원본 필드 전체, 각 와인의 잔량, 와인잔 필드, 취향 기록을 대조했습니다. 파서 회귀 테스트 9개와 해당 파일 ESLint가 통과했습니다.

운영 DB에서도 전체 원본 필드와 각 와인·잔·취향 기록의 일치를 확인했습니다. 재실행 결과 와인 64건·와인잔 5건 모두 건너뛰어 중복 생성되지 않았습니다. 운영 데이터 반영은 완료했으며, 이는 일회성 이관으로 Airtable과 자동 동기화되지 않습니다.
