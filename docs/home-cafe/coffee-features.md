# 커피 페이지 동작 기준

2026-09-09 구현 기준. 원본 DESIGN.md의 이미지 요구사항보다 이 문서를 우선한다.

- `/coffee`는 사진 없는 정보형 목록이다. PC에서는 원두/가격/평가/최근 머신 세팅 열로 비교하고, 모바일에서는 원두·가격과 평가·세팅을 두 줄로 배치한다. 상세에서도 가상 이미지를 사용하지 않는다.
- `price`는 한 포장의 판매 가격(원)이다. 중량이 비어 있어도 가격을 표시하며 0원과 미입력을 구분한다. `weight_g`가 있을 때만 1kg 환산 가격을 계산한다. 중량이 없다고 1kg 제품으로 추정하지 않는다.
- 이름순, 브랜드순, 판매 가격 낮은순/높은순, 1kg 가격 낮은순을 제공한다. 가격을 계산할 수 없는 항목은 가격 정렬에서 마지막이다. 동일 가격은 이름순이다.
- 검색 대상은 원두명·브랜드명·맛과 향이다. 브랜드·경험·추천·평가 사용자·보관함 필터와 초기화를 제공한다. 전체 사용자 선택 시 각 사용자 평가를 표시하며 경험과 추천 조건은 동일 사용자의 평가에서 일치해야 한다.
- 평가 내용은 사용자별로 분리하지만 추천 집계는 공유한다. 목록의 평가 열은 평가 사용자 필터와 무관하게 `추천 N명`을 항상 표시하고, 추천한 구성원 이름을 title로 제공한다.
- 추천 칩의 `누군가 추천`(`recommend=any-추천`)은 구성원 중 한 명이라도 추천한 원두를 남긴다. 나머지 추천 칩과 경험 필터는 선택한 평가 사용자 기준을 유지한다.
- 머신 세팅은 로그인한 사용자의 최근 기록이다. 분쇄도와 용량은 기기의 설정 숫자이며 g 단위가 아니다. 평가 사용자 필터로 머신 기록의 주체가 바뀌지 않는다.
- 브랜드 이름과 원두 수 링크는 해당 브랜드의 보관하지 않은 원두 목록으로 이동한다. 수량도 동일 기준이다. 원두 목록의 브랜드 링크는 브랜드 탭의 해당 카드로 이동한다. 브랜드/원두 탭 왕복과 상세의 목록 복귀 링크는 검색·필터·정렬을 보존한다. 상세 브랜드 링크는 그 브랜드 전체 원두를 여는 별도 동작이다.
- URL 키: `q`, `brand`, `recommend`, `status`, `person`, `archived`, `sort`. 데모도 `view`와 별도로 동일 쿼리를 전달하며 실제 DB나 저장 API를 사용하지 않는다.
- 웹 등록/수정 폼에서 원두 이미지 입력은 제공하지 않는다. 기존 `image_url` 데이터와 MCP 계약은 호환성을 위해 유지하며 수정 폼으로 기존 이미지 값을 지우지 않는다.

구현: `src/components/app-shell.tsx`, `src/app/globals.css`. 서버 데이터와 MCP 계약 변경, DB migration은 없다. 회귀 검증: `tests/e2e/app.spec.ts`의 coffee prices 테스트가 중량 없는 가격, 0원, 미입력, 가격 정렬과 브랜드 왕복을 PC/모바일에서 확인한다. 테스트는 로컬 `_test` DB만 사용한다.
